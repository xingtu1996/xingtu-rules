- 工作分支：`work/xrule-rule-inventory-20261102`；当前 Draft PR：无。

## 目标

将 XRULE 定位为可解释、自描述、可组合、可验证的 Agent 工程规则资产库；说明它与 `AGENTS.md`、`CLAUDE.md`、Skills、Hooks、SDD、Harness 的边界，形成有来源的矩阵组合说明和最小 Rule Pack 契约，并在权属准入通过后验证一个样本。

Rule 是对 Agent 行为或交付产物施加、且具有明确适用条件的工程约束。它不是模型控制层、安全沙箱或强制权限系统。规则文本被加载、模型遵循、工具层检查是不同状态。

## 范围

1. 校正 README 与 SELF 中关于规则结构、加载及跨平台兼容的绝对表述。
2. 定义 Rule Pack 元数据字段：身份/版本、意图与理由、适用/不适用范围、依赖/冲突、平台能力状态、验证入口、来源与发布审查状态。
3. 说明资产职责：主指令给项目入口；Rules 给具体约束；Skills 给任务方法；Hooks 做运行时工具事件检查；SDD 定义单任务规格与验收；Harness 组织和交付资产。关系不暗示固定调用顺序。
4. 建立来源与证据台账：官方平台文档/研究/矩阵实现/本地候选分别标注来源、核验日期、版本、限制、推论和所需验证。
5. 盘点本地规则仅到主题级；追踪来源仓、作者/许可证和授权。权属不明、客户/雇主专属或第三方许可不清的材料不得进入公共样例。
6. 权属准入后选一个样例，独立撰写并提供适用/不适用说明及正反例；优先验证一个明确目标运行时，其余标 `not-tested`。

## 非目标

- 不开发通用注册中心、复杂依赖解析器或运行时插件平台。
- 不修改 xingtu-hooks、xingtu-harness 或本地源项目。
- 不自动安装插件、改变真实 Agent 配置、合并 PR、发布版本或宣称未验证平台兼容。
- 不因脱敏而推定取得版权或雇主授权。

## 阶段闸门

- G0 进入：任务、边界、基线和验收写明；已完成。
- G1 事实：官方资料、论文、Harness 文件和本地源仓逐项核实；没有证据的主张标 UNKNOWN。
- G2 设计：Rule Pack 契约与矩阵图区分已实现/建议；由独立审查者攻击误导性表述和隐含承诺。
- G3 样例：来源权属准入通过，或选用全新独立撰写样例；不得以去名/改路径替代授权。
- G4 验证：正反例、元数据检查和目标运行时实测均记录；未测平台不标兼容。
- G5 交付：隐私扫描与文档一致性检查通过，提交隔离分支并开 Draft PR；人工审核后再决定后续动作。

## 验收与失败判据

- README/SELF 不再将文件放置等同于自动生效；Rules 与各相邻资产职责有清晰定义。
- 每个兼容条目包含官方来源、核验日期、能力边界和测试状态；缺项即不通过。
- 研究条目采用“研究发现 → XRULE 推论 → 局限 → 本地验证”，不得称为对 XRULE 的背书。
- 依赖图每条实装边附仓库文件证据；建议边显式标为建议。无法证明的边不得画成现状。
- 元数据字段、正反例及其预期结果可机械检查或明确人工判据；缺少失败条件即不通过。
- 任何权属待确认或来源含敏感信息的本地规则不得进入公开变更；隐私扫描失败即停止 PR。
- 运行时验证必须记录实际版本、加载位置/配置、可观察证据；只检查文件存在不算加载通过。

## 对抗审查结论与处置

独立审查已发现：范围过大可能稀释核心验证；平台行为和论文状态会漂移；脱敏不等于授权；Harness 关系可能混淆克隆、安装、加载、遵循与强制；本地来源 Git 跟踪和权属未知；原验收过于主观。处置是分阶段闸门、逐项证据、独立权属准入和明确失败判据。审查原始结果由主会话保留，不将未核实的附件主张写为事实。

## 回退

所有改动限隔离分支和文档/样例；不推送主分支、不自动合并。发现来源或兼容证据不足时，撤回相关公共样例/声明，保留只读审计记录；通过提交回退或后续修订恢复到基线。
